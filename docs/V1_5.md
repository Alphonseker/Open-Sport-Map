# **V1.5 Step-by-Step Achitecture**

## **1. Augment the dataset with OSM**

### **1.1 Scaled Regional Pipeline: OSM Protocolbuffer (PBF) & Osmium**

While the Overpass API is suitable for small city-level extractions (e.g. Valenciennes in the V1), scaling to regional or national coverage introduces HTTP 504 Gateway Timeouts due to the high density of `leisure=pitch` polygons across hundreds of municipalities.

To achieve production-grade scalability, Open Sport Map implements a binary extraction workflow based on [Geofabrik](https://download.geofabrik.de/europe/france/nord-pas-de-calais.html) regional dumps and [Osmium](https://osmcode.org/libosmium/).

```text
[ Regional .osm.pbf ]
             │
             ▼  (osmium tags-filter inside isolated Docker container)
[ Filtered sports binary ]
             │
             ▼  (osmium export with '-a type,id' attributes)
[ Raw GeoJSON with Polygons & Points ]
             │
             ▼  (clean_osm_data.py: Centroid calculation & Argparse CLI)
[ Normalized Point GeoJSON (EPSG:4326) ]
             │
             ▼  (load_geojson_to_postgis.py --input <path>)
[ PostgreSQL 16 / PostGIS (facilities table) ]
```

---

#### **1.1.1 Headless Extraction via Ephemeral Docker Container**

Rather than compiling C++ binaries or installing complex geospatial packages on the host operating system, the extraction relies on an ephemeral, throwaway Debian container executing `osmium-tool`:

```powershell
docker run --rm -v "${PWD}/data:/data" debian:bookworm-slim bash -c "
  apt-get update -qq && apt-get install -y -qq osmium-tool && \
  osmium tags-filter /data/raw/nord-pas-de-calais-latest.osm.pbf \
    n/leisure=pitch,fitness_station,track \
    w/leisure=pitch,fitness_station,track \
    -o /data/raw/sports_npdc.osm.pbf --overwrite && \
  osmium export /data/raw/sports_npdc.osm.pbf \
    --geometry-types=point,polygon \
    -a type,id \
    -o /data/processed/facilities_npdc.geojson --overwrite
"
```

**Technical Details:**
- **In-Memory Filtering (`tags-filter`):** Evaluates nodes (`n/`) and ways (`w/`) matching target sport facilities directly over Protocol Buffers in seconds without disk overhead.
- **Metadata Retention (`-a type,id`):** Crucial flag ensuring native OSM entity identifiers (`@id`, `@type`) are preserved in the GeoJSON output for subsequent deduplication and unique constraint handling.

---

#### **1.1.2 Python CLI & Geometric Centroid Normalization (`clean_osm_data.py`)**

A primary technical challenge when moving from Overpass to raw OSM exports is that sport facilities are predominantly mapped as bounding boundaries (`Polygon` or `MultiPolygon`) rather than isolated points (`Point`). 

Because the PostGIS destination column is typed as `GEOMETRY(Point, 4326)`, polygons cannot be inserted directly. The cleaning script performs algorithmic dimensionality reduction by calculating spatial centroids:

$$\text{Centroid}_{\text{lon}} = \frac{1}{N} \sum_{i=1}^{N} \text{lon}_i, \quad \text{Centroid}_{\text{lat}} = \frac{1}{N} \sum_{i=1}^{N} \text{lat}_i$$

The script was refactored with Python's `argparse` module, supporting both backward-compatible default paths and parameterized execution:

```powershell
# Usage with arbitrary inputs and outputs:
python data/scripts/clean_osm_data.py -i data/processed/facilities_npdc.geojson -o data/processed/facilities.geojson
```

**Core Responsibilities:**
1. **Centroid Reduction:** Translates polygon rings into single geographic coordinates.
2. **Schema Uniformity:** Normalizes heterogeneous tags (`leisure=pitch`, `sport=basketball,soccer`) into standardized categorical sport identifiers.
3. **Resilient Identity Resolution:** Fallbacks across `@id`, `id`, and synthetic hashes to prevent silent element drops during parsing.

---

#### **1.1.3 Database Ingestion (`load_geojson_to_postgis.py`)**

The ingestion script similarly incorporates CLI arguments, enabling batch ingestion of any normalized GeoJSON dataset into PostGIS:

```powershell
python data/scripts/load_geojson_to_postgis.py -i data/processed/facilities.geojson
```

- Inserts records using binary EWKT representations (`ST_GeomFromEWKT('SRID=4326;POINT(...)')`).
- Maintains idempotency through PostgreSQL's native upsert:
  `ON CONFLICT (source, source_id) DO UPDATE SET ...`
